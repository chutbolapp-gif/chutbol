# supabase/

Database for Chutbol: migrations, RLS, seed and SQL tests. CLI: the `supabase` npm package in the
repo root (`node node_modules/supabase/dist/supabase.js …`, or `pnpm exec supabase …`).

| File | What |
| --- | --- |
| `migrations/` | Schema + RLS, as SQL files. Never edit an applied migration; add a new one. |
| `seed.sql` | GENERATED by `pnpm import:seed` (scripts/import-prototype) from docs/prototype/data. Real league + 3 dev test phones. |
| `tests/database/*.test.sql` | pgTAP tests (`supabase test db`): RLS for anon / member / admin A / admin B / outsider, and the import. |
| `config.toml` | Local stack config. Phone OTP on, test numbers in `[auth.sms.test_otp]`. |

## Local (needs Docker Desktop running)

```powershell
pnpm exec supabase start        # first time downloads the images (several GB)
pnpm exec supabase db reset     # migrations + seed
pnpm exec supabase test db      # pgTAP tests
pnpm exec supabase stop
```

Studio: http://127.0.0.1:54323. The phone cannot reach this local stack; Expo Go on a phone uses
the remote project (apps/mobile/.env).

## Remote project (yjsjkziinpjaiduufbbp, eu-west-1)

Only after the local tests pass:

```powershell
pnpm exec supabase login                              # once, in the browser
pnpm exec supabase link --project-ref yjsjkziinpjaiduufbbp   # asks for the database password
pnpm exec supabase db push --include-seed             # migrations + seed
pnpm exec supabase config push                        # auth settings: phone login, test numbers
```

No service_role / secret key is needed for any of this, and none is stored in the repo.
